# CM 2026-10-17 裁决：#771 止血由 HOME 侧 agent 发审批单执行

## 裁决原文要点

1. 采纳识别卡 **AC-0043 的方案 A**：**批准由 HOME 侧 agent 发审批单执行止血**，
   止血动作＝清生产 state 会话指针 ＋ 引导员工发 `/new` 重建会话（CM 评：30 分钟内可完成）。
2. 中台 #1624（管家呈裁）同步拍板：采纳选项 1（同上，最快路径）。
3. 本条不含「免审批直改生产」的授权——执行仍必须走 approval-form 通道 B（申请单 → gatekeeper 剧本）。

## 裁决之后的实况变化（2026-10-17 本会话实测，须与裁决同读）

1. 生产桥已随 0.8.9–0.8.14 合批升到 **0.8.14**，且该版本**已带 #771 的自动重建腿但没有单次熔断**
   （字节级钉死：生产 index.js sha256 与本地提交 `1d5702a` 的 blob 一致，`073bec2553…c203a6`）。
   ⇒ 无熔断时「每一条入站消息重建一次、每次换会话 id」＝员工历史被反复隔离，
   这是裁决当时未登记的更大风险面。
2. 「清 state 会话指针必须配合重启才生效」：`loadChats()` 只在 bot 首次创建时调用一次
   （`index.js:6674`），运行中改 state 会被下一次 `persistChats()` 用内存旧态整体覆盖。
   ⇒ 出处 #342 报告里「state 热读、无需重启」的写法不成立，已在 CHANGELOG 0.8.15 段更正。
3. 「清空 hr 各 chat 指针」会把**健康会话**的历史一并丢掉（全量清 ＝ 全体付代价），
   而挂载丢失只发生在 resume 腿的旧会话上。⇒ 是否仍按全量清，已另摆方案请 CM 拍（见下）。
